# 00-3 教师准备与验收

## 发布前准备

- 确认 00-2 已经完成并推送到各学生个人仓库 `main` 的对应任务文件夹。
- 告知学生在个人仓库中建立 `00-3-读懂并修改程序` 文件夹，将代码与学习记录放在其中，并直接推送到 `main`；不创建 PR 或任务分支。
- 总结统一使用阶段 00 的 `任务总结模板.md`；允许学生把三种检查结果压缩写在证据一栏。
- 发布前阅读 starter 和参考行为，保证成功取消、未报名者取消、空名单三种情境可判定。
- 将本任务作为阶段 00 的 Python 基础整合点：变量和常见类型、列表/字典、条件、循环、函数、参数与返回值。先让学生完成短预测和循环练习，再进入取消功能；避免一次引入类、模块拆分、异常处理等额外内容。
- 为 Python 未能启动的学生提供工具排错支持；不要让环境问题遮住代码理解目标。

## 验收标准

| 项目 | 量化验收标准 | 证据位置 |
| --- | --- | --- |
| 提交文件 | 任务文件夹内有 3 个文件：`activity_signup.py`、`测试记录.md`、`任务总结.md` | GitHub 文件列表 |
| Python 基础热身 | 完成 7 项：3 个类型判断、1 个表达式解释、1 个条件解释、1 个函数参数/返回值说明、1 个 `for` 循环 | `activity_signup.py` 中注释/代码；现场提问 |
| 取消功能 | 成功取消返回 `True` 且移除 1 人；失败取消返回 `False` 且名单不变 | 代码与测试记录 |
| 测试覆盖 | 3/3 情境有记录：成功取消、未报名者、空名单；每项写明输入/初始状态、预期、实际结果 | `测试记录.md` |
| 结果正确 | 3/3 情境实际结果符合预期，至少能核对返回值和名单；成功取消另核对剩余名额 | `测试记录.md` 或运行结果 |
| 个人理解 | 随机抽 1 个情境，学生先预测返回值和名单变化，再运行核对；另能解释 4 个基础概念 | 现场口头检查 |
| 总结与提交 | `任务总结.md` 简短填写；任务文件夹推送至个人仓库 `main`；根目录 README 未改 | GitHub 与总结 |

建议采用“全部关键项通过，或补做后复核”的方式，不用代码风格细节扣分。AI 可以参与实现；必须保留学生自己的测试记录，并通过现场预测与解释确认理解。学生直接把本任务文件夹推送到个人仓库 `main`，后续任务继续使用同一仓库并放入新的对应文件夹。

## Python 基础融入方式

本任务不是要求学生一次掌握完整 Python，而是提供后续读代码和做 Web 任务所需的最小基础。概念都从同一段报名程序中出现，采用“指出语法—预测结果—运行验证—修改应用”的路径：

| 基础概念 | 任务中的落点 | 学生应能做到 |
| --- | --- | --- |
| 变量与类型 | `name`、`capacity`、`attendees` | 分辨字符串、整数、列表，读懂赋值 |
| 列表与字典 | `events`、`event["attendees"]` | 通过键取值，说明列表保存报名者 |
| 表达式与内置函数 | 减法、`len()` | 手算剩余名额并解释计算 |
| 条件与布尔值 | `if`、`in`、`True`/`False` | 预测分支是否执行及函数结果 |
| 循环 | 遍历报名名单 | 用 `for` 逐项处理列表 |
| 函数 | `remaining_seats`、`sign_up`、`cancel_signup` | 识别参数、调用、返回值及副作用 |

循环热身只要求加入简单遍历；取消报名功能承接条件、列表操作和返回值。避免把语法练习扩张成独立题库，否则会冲淡读懂并维护现有程序的目标。若学生完全零基础，可在正式修改前用 10—15 分钟演示变量、列表/字典、`if` 和函数调用，再让学生完成任务内的预测题。
