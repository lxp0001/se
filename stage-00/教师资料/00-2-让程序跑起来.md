# 00-2 教师准备与验收

## 发布前准备

- 发布 Windows 安装指南或校内软件中心指引，至少包括 VS Code、Git、Python 3 和 Node.js；说明 Python 命令是 `python` 还是 `py`。
- 确认学生使用个人仓库，并能按课程说明提交任务文件夹或仓库链接。
- 说明每项任务成果放入独立文件夹，直接提交并推送到个人仓库 `main`；本课程不创建 PR 或任务分支。
- 提供统一的 `任务总结模板.md`；学生只需简短填写自己的判断、证据和解释，不修改仓库根目录 README。
- 提醒学生不要在作业中提交密码、Token 或含个人信息的终端路径截图。

## 验收标准

| 项目 | 通过表现 |
| --- | --- |
| 环境 | `00-2-让程序跑起来/环境检测报告.md` 中主机名及 Python、Git、Node.js、VS Code 检测结果逐项单行列出，主机名允许遮盖；VS Code 可手动确认，不强制配置 `code` 命令 |
| 运行 | 能在终端中从仓库目录运行程序 |
| 排错 | 能从 `debug_practice.py` 的 Traceback 找到文件、行号和错误名称 |
| 验证 | 修复后重新运行并观察到预期输出；任务总结简要说明修复与验证 |
| 解释 | 能简要说明 AI 建议是否有帮助，以及如何核验 |
| GitHub | 任务文件夹已提交到个人仓库 `main`，教师可访问 |

本任务建议采用通过／补做。版本号差异不影响通过；操作系统安装、PATH 和权限问题应提供协助，不用来评判编程能力。`env_check.py` 会检测主机名、Python、Git、Node.js 和 VS Code（含 Windows 常见安装位置），逐项单行输出并生成 UTF-8 编码的 `环境检测报告.md`。VS Code 未被脚本发现时，学生可手动确认是否已安装、能否打开；不要求配置 `code` 命令，Windows 自定义安装路径或 macOS 未配置命令时可能无法自动检测。主机名属于设备识别信息，允许学生遮盖后提交。`debug_practice.py` 是课程报名汇总程序，预设错误为函数中使用了未定义的 `student_list`，应从 `NameError` 和行号定位，并使用函数参数 `names` 修复。修复后应显示课程名、3 名报名者、9 个剩余名额及名单。
