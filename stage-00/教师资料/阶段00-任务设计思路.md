# 阶段 00：任务设计思路

## 阶段定位

阶段 00 是软件工程课的基础准备阶段，不以讲完某门编程语言为目标，而是让零基础学生尽早进入可持续的工作循环：理解任务、形成自己的判断、动手操作、观察证据、解释结果，并将成果保存在个人 GitHub 仓库中。

四项任务按“协作与提交 → 环境与运行 → 阅读和修改程序 → 浏览器与 Web 请求”递进。学生从第一项任务开始就使用自己的 `software-engineering` 仓库；每项成果独立放入对应任务文件夹，直接推送到 `main`，不要求 PR。仓库根目录 `README.md` 保持原样，任务总结放在各自任务目录内。

贯穿全阶段的学习结构是“先自己想，再用 AI”：先记录预测或初步做法，再执行任务、收集可观察证据，最后用自己的话解释；可以使用 AI，但需核对建议并如实说明。这样既让 AI 成为可用的学习工具，也保留学生独立判断和解释的证据。

## 00-1：提交第一份代码

**设计意图：** 把 GitHub 协作流程放在编程练习之前。课程后续依赖每位学生提交自己的代码，因此先建立个人仓库、克隆、查看修改、commit 和 push 的最小闭环。

**学习重点：** 区分工作区、本地提交记录和 GitHub 上的仓库；理解 `commit` 保存本地版本、`push` 上传提交；知道课程成果按任务文件夹组织。

**为何使用极小程序：** 一行问候程序只提供可见、可核对的成果，不让 Python 语法或调试分散首次 Git 学习的注意力。程序运行不是本任务门槛。

**思考与评价：** 操作前预测程序输出和 commit/push 的差别；完成后用终端与 GitHub 页面核对。评价关注提交流程及学生能否解释，而非代码难度或是否使用 AI。

## 00-2：让程序跑起来

**设计意图：** 先确认学生的开发环境是否可用，再通过一个有明确错误线索的小程序练习运行和排错。环境问题与代码理解分开处理，避免把安装、PATH 或权限问题误判为编程能力不足。

**学习重点：** 从仓库目录打开终端、运行 Python 脚本、阅读 Traceback 中的文件和行号、识别错误名称、修改后重新验证；同时建立可提交的环境检测记录。

**工具取舍：** 检测脚本给出主机名以及 Python、Git、Node.js、VS Code 的版本或可用性。VS Code 检测允许手动确认，不强制配置 `code` 命令，以兼顾 Windows 安装路径和不同操作系统差异。主机名可遮盖。

**思考与评价：** 学生先预测运行结果或错误位置，再根据实际报错修复。通过标准看能否解释“证据—定位—修改—复测”，而不是要求所有机器版本完全一致。

## 00-3：读懂并修改程序

**设计意图：** 从单文件中的变量、函数和列表进入基本程序理解，先读现有代码、追踪状态变化，再修改已有行为，而不是从空白开始编写。

**学习重点：** 将后续读代码所需的 Python 最小基础融入真实程序：变量与常见类型、列表和字典、表达式与 `len()`、条件与布尔值、循环、函数参数和返回值。学生先解释和预测语法效果，再追踪函数调用如何改变名单与剩余名额，最后实现取消报名并用正常和边界情境检验行为。

**任务结构：** 以课程报名管理作为具体情境，通过“阅读—预测—运行—修改—测试”连接概念与可观察结果。成功取消、取消未报名者、空名单等情境可用来检查学生是否理解状态和边界。

**思考与评价：** 重点不是代码写得多或背定义，而是学生能否结合程序指出语法、预测执行结果、修改后核验，并解释数据如何变化。用短热身练习（如遍历列表并逐项打印）补足基础，再进入功能修改。允许 AI 辅助实现，但应通过测试和口头追踪证明理解。

## 00-4：看懂网页如何工作

**设计意图：** 在已有运行脚本和读取代码的基础上，转向浏览器中的网页，补足前端与 HTTP 的直观概念，为后续前后端开发建立心智模型。

**学习重点：** 区分 HTML 的内容结构、CSS 的呈现样式、JavaScript 的交互逻辑；在浏览器开发者工具中观察请求方法、状态码和 JSON 响应；理解请求、服务器响应、页面更新之间的数据流。

**任务取舍：** 用本地静态服务器及同源 JSON 文件构成小而完整的网页请求，不引入登录、外部 API、跨域配置或密钥，减少不必要的环境和安全负担。

**思考与评价：** 学生先预测页面显示或请求结果，再通过浏览器网络面板和实际响应核对。评价看能否将观察到的证据连成请求流程，并用自己的话解释三种前端技术的职责。

## 阶段设计的共同原则

- **先证据，后解释：** 预测可以不正确，但必须尝试用运行输出、提交记录、测试结果或网络请求修正自己的理解。
- **小步递进：** 每项任务只引入少量新概念，并复用个人仓库、任务文件夹和简短总结的提交习惯。
- **AI 可用但需核验：** 不以禁止 AI 作为学习保障；要求学生说明是否采纳建议，以及如何用实际证据判断。
- **总结简短、解释可追问：** `任务总结.md` 作为学习线索而非长篇作文；教师可通过简短口头追问确认理解。
- **评价概念而非机器差异：** 安装路径、版本、账号权限及端口等问题应获得支持，不应替代对学生理解的评价。
