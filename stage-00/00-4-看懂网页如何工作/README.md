# 任务 00-4:看懂网页如何工作

本任务通过一个本地网页观察浏览器如何显示 HTML、应用 CSS、执行 JavaScript,并向服务器请求 JSON。顺序是:先运行,再认识三个文件,然后用开发者工具追踪一次请求,最后动手改页面。你不需要会写 HTML、CSS 或 JavaScript,只要能看懂它们各管什么。

## 完成后你应该能够

- 说明 HTML、CSS 和 JavaScript 各自负责什么。
- 从浏览器开发者工具中找到页面发出的请求。
- 读出请求方法、状态码和 JSON 响应中的字段。
- 用自己的话画出浏览器、服务器和响应数据之间的关系。
- 读懂一条浏览器报错,并说明为什么直接双击打开网页会失败。

## 开始前

完成任务 00-3,并确认成果已推送到个人仓库 `main`。准备 Python 3、代码编辑器以及 Chrome 或 Edge 浏览器。任务使用本地静态服务器和附带的 JSON 文件,不依赖外部 API。开始前同步仓库并创建任务文件夹及其中的 `任务总结.md`:

```powershell
git pull
```

然后在仓库根目录新建 `00-4-看懂网页如何工作` 文件夹,把[统一任务总结模板](../任务总结模板.md)复制到其中并命名为 `任务总结.md`。不要修改仓库根目录原有的 `README.md`。

把 `starter/web-demo/` 复制到 `00-4-看懂网页如何工作` 文件夹中。学习过程中随时可以翻阅 [`starter/网页三件套速览.md`](starter/网页三件套速览.md),看不懂的词回来查。

## 第一步:先直接打开网页(会遇到一个报错)

先不要运行任何命令。在文件夹里找到 `web-demo/index.html`,**直接双击**用浏览器打开,再点一下"获取消息"按钮。

页面上会显示"请求失败"。这不是你做错了,是这个任务想让你亲手遇到并弄懂的一个报错。请按顺序做:

1. 看一眼浏览器地址栏,记下它以什么开头。
2. 按 `F12` 打开开发者工具,切到 **Console**(控制台)标签,找到红色的报错,把它复制下来。再切到 **Network** 标签,看有没有出现请求,它的状态是什么。
3. **先自己猜原因**(两三句话,写在草稿里,先不要问 AI):报错里哪个词最关键?为什么这次请求被拒绝了?
4. 猜完再问 AI,并把你的猜测一起发给它。对照第二步的结果,检查 AI 说得对不对。

## 第二步:把网页运行起来

现在换一种方式打开网页,看看它是什么样子:

```powershell
cd 00-4-看懂网页如何工作/web-demo
python -m http.server 8000
```

保持终端窗口运行。在浏览器打开 `http://localhost:8000`,点一下"获取消息"按钮,看看页面上出现了什么。若 `python` 命令不可用,使用 `py -m http.server 8000`。要停止服务器,回到终端按 `Ctrl+C`。

终端里每次有人访问网页,都会多出一行记录。点一下按钮,看看终端有什么变化。

这次按钮应该能正常显示消息了。对比第一步:地址栏的开头有什么不同?Network 里的请求又有什么不同?

## 第三步:认识三个文件

用编辑器依次打开 `index.html`、`styles.css`、`app.js`。文件里已加上中文注释,先读注释,不需要看懂每一行。

读完后,对照速览里的"三个文件,三种分工"表格,用一句话写下:

- `index.html` 负责 ______
- `styles.css` 负责 ______
- `app.js` 负责 ______

## 第四步:先预测,再观察

**先预测**(写在草稿里,不要问 AI):

1. 点击按钮后,网页上的那句话是从哪里来的?你认为浏览器会收到什么?
2. 如果修改 `styles.css` 里标题的颜色,页面哪个部分会变?

**再观察。** 打开开发者工具:在 Chrome 或 Edge 中按 `F12`,选择 Network(网络)标签,按下面的步骤操作(细节见速览第五节):

1. 勾选 **Disable cache**(禁用缓存)。
2. 点一下"清空"图标,再刷新页面。
3. 在筛选里选 **Fetch/XHR**。
4. 点击页面上的"获取消息"按钮。
5. 在列表里点击 `message.json`,分别在 Headers 和 Response 里找到并记录:
   - 请求方法;
   - 状态码;
   - 响应中的 `message` 字段内容。

状态码一般是 200。如果你看到 304 或"(disk cache)",是浏览器用了缓存,属于正常现象,把实际看到的记下来。

再选择 Elements(元素)标签,在页面结构里找到 `<h1>` 和 `<button>`,看看它们和 `index.html` 里的写法一样不一样。

## 第五步:动手改一改

每次改完后保存文件,在浏览器里按 `Ctrl+F5` 强制刷新:

- 在 `index.html` 中将标题和说明改成你自己的示例(注释里标有"任务第三步");
- 在 `styles.css` 中修改页面背景色或标题颜色(注释里标有"任务第三步");
- **不要修改** `app.js` 中的 `fetch` 请求那一行。

改完后再点击"获取消息"按钮,回到 Network 确认新请求仍然成功,并记下改动后的页面表现。

## 第六步:用 AI 对照解释

先保留自己的预测,再向 AI 询问**一个**具体概念,例如"这个页面中哪段代码发出 HTTP 请求?"或"状态码 200 表示什么?"。提问时带上具体的代码或你看到的现象,示范见速览最后一节。不要上传浏览器 Cookie、令牌或账号信息。

对照文件和开发者工具检查 AI 的解释:它说的和你在 Network 里看到的一致吗?

## 第七步:画出请求流程

按统一模板填写 `00-4-看懂网页如何工作/任务总结.md`。在证据一栏记下 `message.json` 请求方法、状态码和响应内容;在自己的解释中用一行文字写出请求流程:

```text
浏览器中的 JavaScript → 请求 message.json → 本地服务器返回 JSON → 页面显示消息
```

再用简短词语说明 HTML、CSS、JavaScript 各自负责什么,并记下请求方法、状态码,以及你如何用页面证据核对 AI 的解释(一句话即可)。

另外用两三句话记录第一步的排错:直接双击打开时看到了什么报错、你最初的猜测是什么、最后弄清的原因是什么,以及换成 `http://localhost:8000` 之后有什么不同。
