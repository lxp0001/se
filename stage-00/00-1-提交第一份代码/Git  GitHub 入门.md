## Git / GitHub 入门(含注册与注意事项)

### 一、先搞懂两个东西

- **Git**:装在你电脑上的"带历史的存档工具",断网也能用。
- **GitHub**:存放 Git 仓库的网站,相当于云备份,也是你的作品集。
- 类比:Git 是抽屉里的记账本,GitHub 是银行。

### 二、为什么要学

1. **备份有历史**:改坏了能回到任何一个旧版本。
2. **可以放心试错**:新想法放在分支上,不行就丢掉。
3. **作品集**:找实习、找合作时,别人会看你的 GitHub 主页。
4. **控制 AI**:AI 会一次改很多文件,有 Git 才能看清它改了什么,不满意就回退。

### 三、注册 GitHub(一步步来)

1. 打开 github.com,点右上角 **Sign up**。
2. **邮箱**:建议用 Gmail、Outlook 等,国内邮箱有时收不到验证邮件。能用学校邮箱的话,后面还可以申请学生优惠(GitHub Education)。
3. **用户名**:它会出现在你所有仓库的网址里,也会出现在简历上。用拼音名或固定的网名,不要用 `xiaoming123` 这种。一旦定了,尽量不改。

### 四、安装与配置(一次性)

1. 安装 Git:Windows 去 git-scm.com 下载,一路下一步;Mac 可以用 Homebrew 安装。
2. 配置名字和邮箱,**邮箱要和 GitHub 注册邮箱一致**,否则你的提交不算在你账号下(头像是灰的,贡献格子也不亮)。
3. 配置登录方式,二选一:
   - **浏览器授权登录**:Windows 上的 Git 自带登录助手,第一次推送时会弹出浏览器,点授权即可,最省事。
   - **SSH key**:在本地生成密钥,把公钥添加到 GitHub 的 SSH keys 里,之后推送不用输密码。建议让老师带着做一遍。

### 五、四个核心概念

| 概念 | 一句话                                                 |
| ---- | ------------------------------------------------------ |
| 仓库 | 被 Git 管起来的文件夹,里面有个隐藏的 `.git`,**不要删** |
| 提交 | 给当前状态拍一张快照,附一句说明                        |
| 分支 | 一条平行的"草稿线",改坏了丢掉,主线不受影响             |
| 远程 | GitHub 上对应的那个仓库                                |

### 六、日常工作流程

**改文件 → 看改了什么 → 提交 → 推送到 GitHub**

只需要记住三个命令:

bash

```
git add <本次任务文件夹>
git commit -m "写清楚这次改了什么"
git push
```

不知道该干什么时,输入 `git status`。

提交说明要具体。"修复登录按钮点不动"是好说明,”更新"”修改"不是。

### 七、和 AI 一起用

- 让 AI 动手**之前**,先提交一次,当作"存档点"。
- AI 改完后,先看它改了什么,再决定接受还是回退。
- 本阶段每项任务把对应文件夹提交到自己的 `main` 分支；以后学习团队协作时再练习分支工作流。
- 最后出问题,责任在提交的人,不在 AI。

### 八、本课程任务的提交方式

每项任务使用仓库中的独立文件夹。完成后只暂存本次任务文件夹，提交并推送到自己的 `main` 分支；团队项目中的分支与代码评审流程将在后续学习。

### 九、注意事项

**账号与登录**

1. 网页登录用账号密码,但**用 Git 推送代码时不能直接用账号密码**,要用浏览器授权、SSH key 或令牌(PAT)。
2. 令牌(PAT)只显示一次,生成后立刻复制保存。丢了只能删掉重建。
3. 令牌、密码不要发给别人,也不要写进代码里。

**仓库安全**

4. **不要把密码、API key、.env 文件提交上去。** 删文件没用,历史里还在。用 `.gitignore` 文件提前排除。一旦泄露,直接作废并重新申请密钥。
5. **不要删 .git 文件夹。** 删了所有历史就没了。
6. **单个文件超过 100MB 推不上去。** 视频、数据集这类大文件不要放进仓库。
7. 公开仓库谁都能看到,放之前想一想:有没有个人信息、手机号、学号、密钥?

**使用习惯**

8. 本阶段任务按要求直接提交到 `main`；团队项目则遵循团队约定使用分支和评审流程。
9. 一次提交只做一件事,说明写清楚。
10. 每次让 AI 大改前先提交一次。
11. 作业项目如果老师要求保密,用**私有仓库**,不要设成公开。
12. 访问慢或下载不下来,多半是网络问题,换时间或网络再试。

### 十、读别人的项目

- 不要从第一行读代码。先读 README,再把项目跑起来。
- 挑一个小功能,顺着它走一遍,不用读懂全部。
- 在 GitHub 网页上,按 `t` 搜文件,按 `.` 打开网页版 VS Code。

### 一句话总结

**Git 在本地,GitHub 在云上。日常就是"改、提交、推送",AI 帮你敲命令,但你要看得懂它做了什么。**
