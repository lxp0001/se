# 任务 00-1：提交第一份代码

这是本课程的第一次提交。你将创建自己的 GitHub 仓库，在对应的任务文件夹中添加一个小程序和学习记录，并把提交推送到 GitHub。每项任务的成果都放在自己的任务文件夹中。重点是先理解本地修改、提交记录和 GitHub 仓库之间的关系。Python 程序的运行和调试将在 00-2 学习。

## 完成后你应该能够

- 在自己的电脑上找到个人课程仓库，知道本地文件与 GitHub 上的仓库有什么关系。
- 查看修改，使用 `commit` 保存提交记录，并使用 `push` 推送到 GitHub。
- 说出 `commit` 和 `push` 分别做了什么，以及课程任务如何按文件夹整理成果。

## 开始前

准备 GitHub 账号、Git、终端和文本编辑器。教师会提供截止时间、仓库链接的提交渠道，以及仓库访问方式。个人仓库可以设为私有；如果设为私有，请按课程提供的仓库访问说明授予教师查看权限，不要把仓库改为公开来解决访问问题。本任务直接提交到自己的 `main` 分支。

以下命令中的 `<你的GitHub用户名>` 是占位符，输入时要换成自己的信息；尖括号本身不用输入。Windows 可在 PowerShell 或 VS Code 的终端中运行这些命令。

## 第一步：创建并克隆个人仓库

在 GitHub 上新建名为 `software-engineering` 的仓库，勾选“添加 README 文件”，使仓库从一开始就有 `main` 分支。请勿把访问令牌、密码或个人敏感信息放进仓库。然后复制仓库页面显示的 HTTPS 地址，在终端检查 Git 并克隆仓库：

```powershell
git --version
git clone https://github.com/<你的GitHub用户名>/software-engineering.git
cd software-engineering
```

本任务直接在仓库初始的 `main` 分支上操作。若提示 Git 身份未设置，按终端提示设置提交使用的姓名和邮箱；两者不需要与你的公开昵称相同。

在仓库根目录创建 `00-1-提交第一份代码` 文件夹，把[统一任务总结模板](../任务总结模板.md)复制到其中并命名为 `任务总结.md`。保留仓库根目录原有的 `README.md`，不要修改它。

同时把本任务提供的[`.gitignore` 模板](.gitignore)复制到**仓库根目录**。它会帮助 Git 忽略本地 `.env`、Python 缓存、虚拟环境和 SQLite 数据库文件；`.gitignore` 是普通文本文件，可以提交。不要把真实密钥写进代码或提交到仓库。若需要展示环境变量名称，可以另提供不含真实值的 `.env.example`。

可以参考[任务 00-1 提交示例](提交示例/00-1-提交第一份代码/)，了解文件组织和总结填写方式。示例中的昵称、运行结果和 AI 使用情况仅供格式参考；请提交自己的程序、实际观察结果和真实的 AI 使用记录。

## 第二步：先自己想

在使用 AI 前，先自己想一想：

1. 程序会显示什么？
2. 你认为 `commit` 和 `push` 有什么区别？

不用提前写成长篇记录，完成后再把结果简要写进 `任务总结.md`。
## 第三步：在任务文件夹中添加第一个程序

在 `00-1-提交第一份代码` 文件夹中创建 `greeting.py`。将下面的程序写入文件，把昵称替换成你愿意让教师看到的称呼：

```python
name = "你的昵称"
print(f"大家好，我是{name}！")
```

按模板简要填写：预测程序输出；记录实际输出作为证据；用一句话说明 `commit` 和 `push` 的区别。AI 使用情况如实填写即可。

已有 Python 环境的同学可以尝试运行 `python 00-1-提交第一份代码/greeting.py`；运行成功不是本任务的必要条件。

## 第四步：提交并推送到 GitHub

先查看修改，再提交本任务文件夹：

```powershell
git status
git add .gitignore 00-1-提交第一份代码
git commit -m "Add my first greeting program"
git push origin main
```

推送成功后，在 GitHub 上打开自己的仓库，确认 `00-1-提交第一份代码` 文件夹中有 `greeting.py` 和 `任务总结.md`。按教师指定渠道提交个人仓库链接，并注明任务文件夹名。

## 第五步：再用 AI，并检查自己的理解

把任务要求和你遇到的**具体问题**发给 AI，例如“解释 `git status` 的输出”或“比较 `commit` 和 `push`”。不要让 AI 代替你点击提交，也不要输入密码、访问令牌或仓库密钥。检查建议是否与你在终端和 GitHub 看到的情况一致，并在任务总结里用一句话记下 AI 是否有帮助。如有修改，再执行 `git status`、`git add .gitignore 00-1-提交第一份代码`、`git commit` 和 `git push origin main`。

## 提交清单

```text
个人仓库/
├── .gitignore
└── 00-1-提交第一份代码/
    ├── greeting.py
    └── 任务总结.md
```

`.gitignore` 放在仓库根目录；`greeting.py` 和 `任务总结.md` 放在本任务目录。仓库原有的根目录 `README.md` 保持不变。按前面的 Git 命令提交并推送后，再按教师指定渠道提交仓库链接。
