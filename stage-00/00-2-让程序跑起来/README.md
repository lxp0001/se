# 任务 00-2：让程序跑起来

本任务把你的电脑准备成可以阅读和运行课程代码的工作环境。你将运行环境检测脚本，检查主机名以及 Git、Python、Node.js、VS Code 的安装情况和可获取的版本信息；再运行一个有小错误的 Python 程序，读懂错误信息并修复它。

## 完成后你应该能够

- 使用脚本检查主机名，以及 Git、Python、Node.js、VS Code 是否可用和相应版本信息。
- 在 VS Code 中打开个人课程仓库，并找到一个 Python 文件。
- 从终端运行 Python 程序，找到报错所指的文件和行号。
- 先自行定位错误，再用 AI 帮助解释，最后通过运行程序验证修复。

## 开始前

完成任务 00-1，并确认代码已推送到你自己的 `main` 分支。需要 VS Code、Python 3 和 Node.js。可用教师提供的安装说明；Node.js 本任务只检查是否安装，不要求编写 JavaScript。脚本会检测 Git 和 Node.js 命令、当前 Python 解释器及常见 VS Code 安装位置。VS Code 的 `code` 命令可能未配置或未被脚本找到；这不影响完成任务，也不要求配置该命令。请手动确认能否打开 VS Code，并在报告中记录即可。主机名可能属于设备识别信息，只在教师要求且你愿意时提交完整值；否则可以遮去部分字符。

开始前先同步个人仓库，并建立本任务文件夹及其中的 `任务总结.md`：

```powershell
git pull
```

然后在仓库根目录新建 `00-2-让程序跑起来` 文件夹，把[统一任务总结模板](../任务总结模板.md)复制到其中并命名为 `任务总结.md`。不要修改仓库根目录原有的 `README.md`。

## 第一步：先自己想

运行程序前，先独立判断：

- 你认为程序文件是如何从 VS Code 变成正在运行的程序的？
- 你认为这个程序的错误可能在哪里？

## 第二步：准备并运行环境检测脚本

把本任务文件夹中的 `starter/env_check.py` 和 `starter/debug_practice.py` 复制到 `00-2-让程序跑起来` 文件夹。在 VS Code 中打开整个仓库文件夹（可用 VS Code 的“文件 > 打开文件夹”），然后在 PowerShell 运行环境检测脚本（若 `python` 不可用，使用 `py`）：

```powershell
python 00-2-让程序跑起来/env_check.py
```

脚本会将主机名和各组件检测结果逐项单行显示，并在脚本所在目录自动生成 `环境检测报告.md`。VS Code 显示未检测到时，请尝试从开始菜单或应用程序中打开它，并在报告中记录“已安装且可打开”或“未安装”；不要求配置 `code` 命令。提交前检查主机名；如不希望公开完整主机名，可在报告中遮盖后再保存。

## 第三步：运行并定位错误

环境检测脚本会正常结束并生成报告。`debug_practice.py` 是一个课程报名汇总小程序，会统计已报名人数、剩余名额并列出报名名单。接着原样运行：

```powershell
python 00-2-让程序跑起来/debug_practice.py
```

如果你使用的是 `py` 命令，则运行 `py 00-2-让程序跑起来/debug_practice.py`。程序会报错。先不要把整段代码交给 AI，也不要立刻改动。阅读 Traceback 的最后几行，判断报错类型、行号和可能的问题位置。

然后打开 `00-2-让程序跑起来/debug_practice.py`，自己尝试修复错误。

## 第四步：用 AI 检查你的判断

向 AI 提供错误信息和相关几行代码，要求它解释错误含义并指出可以检查的位置。先记录自己的判断，再对照 AI 的建议。不要让 AI 直接重写整个文件；不要提交密码、访问令牌、私人路径或其他敏感信息。

修改后重新运行 `00-2-让程序跑起来/debug_practice.py`，确认程序输出课程名称、报名人数、剩余名额和报名名单。

## 第五步：提交本任务成果

### 提交清单

本任务需要提交的文件位于个人仓库的以下目录中：

```text
个人仓库/
└── 00-2-让程序跑起来/
    ├── env_check.py
    ├── debug_practice.py
    ├── 环境检测报告.md
    └── 任务总结.md
```

`env_check.py` 和 `debug_practice.py` 从 starter 复制；前者运行后生成 `环境检测报告.md`，后者需修复并能成功运行。`任务总结.md` 按统一模板填写。提交前检查报告中的主机名，按隐私需要遮盖；仓库根目录原有的 `README.md` 不修改。

1. `env_check.py`：从任务 starter 复制到本任务文件夹，能在本机运行并生成报告。
2. `环境检测报告.md`：由脚本生成，逐行列出主机名和 Python、Git、Node.js、VS Code 的检测结果与版本信息；提交前检查并按需遮盖主机名。
3. `debug_practice.py`：从任务 starter 复制到本任务文件夹，修复后能在本机成功运行。
4. `任务总结.md`：按统一模板简要记录最初判断、报错与修复证据、自己的解释，以及 AI 使用情况；无需长篇反思。

确认以上文件已准备好后，在仓库根目录提交并推送本任务文件夹：

```powershell
git status
git add 00-2-让程序跑起来
git commit -m "Run and debug my Python program"
git push origin main
```

按教师指定渠道提交个人仓库链接，并注明任务文件夹 `00-2-让程序跑起来`。
