# 任务 02-3：报名记录的增删改查

读取 API 已能返回活动信息。本任务让客户端通过 RESTful 风格 API 管理报名记录：新增、查看、修改和删除，并观察服务器用 HTTP 状态码说明成功或失败。

## 完成后你应该能够

- 区分 URL 路径参数与 JSON 请求体。
- 看懂 RESTful 风格下活动报名接口的网址和请求方法。
- 用 FastAPI 接收并验证请求数据。
- 用 SQLite 实现报名记录的新增、查看、修改和删除。
- 为无效请求或不存在的记录返回合理状态码。

## 先想一想

如果请求给出的活动编号不存在，服务器应该假装成功、崩溃，还是给客户端一个错误响应？为什么？先写下预测。

## 开始前

完成 02-2。新建 `02-3-提交报名与处理错误` 文件夹，把自己完成的 02-2 `main.py` 和 `requirements.txt` 复制过来，并复制阶段 00 的任务总结模板。不要复制或提交数据库文件；本任务在当前目录初始化自己的本地数据库。

## 第一步：增加报名数据表

在 `initialize_database()` 中添加 `registrations` 表，字段要求如下：

| 字段 | 类型与要求 |
| --- | --- |
| `id` | 整数主键 |
| `event_id` | 必填整数，关联 `events.id` |
| `username` | 必填文字，保存 `user1`、`user2` 等虚构用户名 |

保留初始化的两条虚构活动数据。

## 第二步：新增报名（Create）

实现 `POST /events/{event_id}/registrations` 新增报名。其中网址表示某场活动的报名集合，`POST` 表示新增；路径中的 `event_id` 指明活动，JSON 请求体提供用户名，例如 `{"username": "user1"}`。仅使用 `user1`、`user2` 等虚构用户名。

检查活动存在后，将报名写入数据库。成功返回报名编号、活动编号和用户名，状态码为 `201`；活动不存在返回 `404`；缺少用户名或类型不正确返回 `422`。任务书不给建表或插入 SQL，学生根据字段要求自行编写。

## 第三步：查看报名（Read）

实现 `GET /events/{event_id}/registrations`，返回该活动的报名记录列表，每条记录包含报名编号、活动编号和用户名。没有报名时返回空列表和 `200`；活动不存在时返回 `404`。在 `/docs` 中查询刚才新增的报名，并观察 JSON 结果。

## 第四步：修改报名（Update）

实现 `PATCH /events/{event_id}/registrations/{registration_id}`，例如 `PATCH /events/1/registrations/1`，请求体使用 `{"username": "user2"}`。接口只修改指定活动中的指定报名记录，不新增另一条记录。

修改成功返回更新后的报名信息和 `200`；报名编号不存在，或该报名不属于网址中的活动时，返回 `404`。在 `/docs` 中把 `user1` 改为 `user2`，再用 GET 确认数据库里的值已更新。

## 第五步：删除报名（Delete）

实现 `DELETE /events/{event_id}/registrations/{registration_id}`，例如 `DELETE /events/1/registrations/1`。删除成功返回 `204`（无响应正文）；报名编号不存在，或该报名不属于网址中的活动时，返回 `404`。先查询确认记录存在，删除后再查询，确认列表中已没有该记录。

停止并重新启动服务器，再次查询报名列表，确认新增、修改和删除操作都实际作用于本地 SQLite 数据。
