# 任务 02-1：启动第一个 Web 服务器

阶段 00 的网页通过静态文件展示内容。本任务让一个正在运行的服务器接收浏览器请求，并返回 JSON 数据。

## 完成后你应该能够

- 说出客户端、服务器、请求和响应的基本关系。
- 知道本任务的 `GET` 请求用于向服务器读取信息。
- 启动 FastAPI 服务，并从浏览器访问接口。
- 使用交互式接口文档查看请求和响应，并探究它的来源。

## 先想一想

浏览器打开一个网址时，电脑另一端的程序怎样把数据送回来？先把预测写进 `任务总结.md`。

## 开始前

完成阶段 01，确认 Python 可运行。同步个人仓库后，在根目录创建 `02-1-第一个Web服务器` 文件夹，把 `starter/main.py`、`starter/requirements.txt` 和阶段 00 的任务总结模板复制进去。

## 第一步：安装并启动服务器

在任务目录的终端安装依赖：

```powershell
pip install -r requirements.txt
```

启动服务：

```powershell
uvicorn main:app --reload
```

终端出现服务器已启动的提示后，保持这个窗口运行。打开浏览器访问 `http://127.0.0.1:8000/`，再访问 `http://127.0.0.1:8000/docs`。

### 自己查一查

打开 `/docs` 后，你可以看到接口并试发请求。回头查看 `main.py`：代码里有没有写 `/docs` 这个网址？如果没有，浏览器为什么仍然能打开它？请查阅 FastAPI 官方文档或其他可靠资料，用自己的话解释，并在 `任务总结.md` 中记下查阅来源。

## 第二步：观察请求和响应

在 `/docs` 页面找到根路径接口并点击 **Try it out**、**Execute**。观察请求网址、请求方法 `GET`、响应状态码和 JSON 内容。这里的 GET 表示向服务器读取信息。关闭服务器后再刷新页面，观察有什么变化；然后重新启动。

## 第三步：修改代码并验证

1. 先预测根路径返回什么 JSON，再启动服务器并核对。
2. 把返回消息中的内容改成你自己的课程提示（不要放真实个人资料），保存并刷新 `/docs` 再次执行接口。
3. 在 `任务总结.md` 里用一句话回顾预测是否正确，并记录实际状态码和响应内容；再回答“代码中没有 `/docs` 路由，为什么这个地址仍然可用？”，附上查阅来源。
