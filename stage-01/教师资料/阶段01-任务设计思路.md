# 阶段 01：任务设计思路

## 阶段定位

阶段 01 承接阶段 00 的 Python 运行、列表/字典和文件阅读基础，建立“数据可以保存在程序之外”的认识，并由直观文件存取过渡到关系型数据库。核心任务是文件存取和 SQLite；第三项是可选的可视化观察，不增加新的编程要求。本阶段不引入 HTTP、服务器或云数据库；这些内容留给后续阶段。

## 三项任务的递进关系

1. **01-1 文件存取：** 以 JSON 作为容易检查的持久化格式。学生亲眼看到程序退出后，数据仍在磁盘文件中；重新读取后，屏幕结果来自文件。
2. **01-2 使用 SQLite：** 引入表、记录、字段、主键和外键的最低限度概念，用两张关联表存活动与报名关系，练习插入、JOIN 和筛选。输入值使用 SQL 参数占位符，尽早形成安全习惯。
3. **01-3（选做）可视化查看：** 使用 DBX 打开 01-2 生成的本地数据库，观察 `events` 与 `registrations` 两张表及它们的关联。它帮助学生把程序代码、SQL 查询与数据库里的实际记录对应起来，不作为新的核心知识点或必交成果。

## 预测—观察—解释

01-1 和 01-2 在动手前提出一个贴合目标的问题，并要求在任务总结里用一句话回顾预测是否正确。预测允许错误；评价重在引用程序输出、文件内容、查询结果或记录数作为证据。01-3 是选做的可视化观察活动，不要求额外总结。

## 安全与隐私习惯

- 全阶段使用虚构姓名、虚构活动，不采集现实个人信息。
- 01-1 起提醒不要在代码或数据文件提交秘密；本阶段明确不需要密钥。
- 复用阶段 00 的 `.gitignore`，将 SQLite 数据库文件（`*.db`、`*.sqlite`、`*.sqlite3`）排除。提交可复现的源代码、非敏感 JSON 样例和文字结果，而非本机数据库文件。
- SQL 查询一开始就使用 `?` 参数占位符，不鼓励把用户输入拼成 SQL。

## 验收重点

- 01-1：文件确实生成；关闭后再次运行仍能读回；学生能区分内存和磁盘。
- 01-2：能建表、插入、关联与筛选；查询实际运行；数据库文件未提交。
- 01-3（选做）：学生能在图形界面中查看表、字段和记录，并说明 `event_id` 如何关联活动；跳过该活动不影响阶段验收。

## 范围取舍

不讲事务隔离、索引原理、数据库范式、并发或线上部署；不要求安装数据库服务器。Python 自带 `json`、`sqlite3`，SQLite 使用本地文件即可完成实践；DBX 仅作为选做的可视化查看工具。这样让学生专注于数据形态、持久化、关系和查询，为阶段 02 的服务器数据接口做好准备。
