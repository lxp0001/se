# 任务 01-1：用 JSON 文件保存并读取报名信息

程序运行时，名单在内存里；程序关闭后，内存内容会消失。本任务用 JSON 文件给活动报名名单做一个“可再次打开的收纳盒”：把数据写进去，重新读取，再显示出来。

## 完成后你应该能够

- 用 Python 将列表和字典保存为 JSON 文件。
- 关闭并重新运行程序，从文件读回数据。
- 解释程序变量和文件各自保存数据的位置。

## 先想一想

程序关掉后，列表里的报名信息会怎样？写进文件就能保住吗？先把你的预测写进 `任务总结.md`，不要担心猜错。

## 开始前

完成阶段 00，确认 Python 可运行，且个人仓库已同步：

```powershell
git pull
```

在仓库根目录创建 `01-1-文件存取` 文件夹，把本任务的 `starter/file_store.py` 复制进去，并从阶段 00 复制[任务总结模板](../../stage-00/任务总结模板.md)为 `任务总结.md`。沿用仓库根目录 `.gitignore`。本任务只用虚构示例数据，禁止录入真实姓名、电话、邮箱等个人信息，也不需要密钥。

## 第一步：先看数据

打开 `file_store.py`，先看 `attendees_in_memory` 和 `saved_attendees` 两个变量。预测程序两次运行时分别会显示什么，再运行核对。

## 第二步：运行演示

先直接运行 starter。它会显示本次运行中只在内存里的名单，并把一份名单写入 JSON 文件；之后再次运行会从文件读回名单。打开代码，找到 `json.dump` 写文件和 `json.load` 读文件的部分，理解它们分别在做什么。

运行：

```powershell
py 01-1-文件存取/file_store.py
```

如果 `py` 不可用，可使用 `python` 命令。第一次运行应在任务目录生成 `registrations.json`；程序每次都会打印内存名单，以及首次保存或从 JSON 读回的名单。

## 第三步：验证“关掉再打开”

1. 第一次运行后查看 `registrations.json`，确认名单实际写入磁盘。
2. 关闭终端，再次运行程序。注意内存名单每次都从 `user1`、`user2` 开始，而 JSON 名单会保留上次新增的用户。
3. **修改代码：**把 `attendees_in_memory.append("user3")` 中的 `user3` 改成 `user4`，运行并对照两份名单。再把 `new_attendee = "user3"` 改成 `new_attendee = "user4"`，运行后查看 JSON。比较这两次代码修改对内存名单和文件名单的影响。
4. 在 JSON 中把一位虚构用户名改掉，重跑程序，确认程序会读到文件里的改动；完成后保留使用 `user4` 的代码和数据。
5. 在任务总结中用一句话写：最初预测是否正确？哪项观察支持你的结论？
